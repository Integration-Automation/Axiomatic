# 其他對話平台

bot 主要住在 Discord，指令樹是原生斜線指令。但**沒有斜線選單的平台**也接得上：
它們重用 bot 一直都有的**文字指令**表面，不另開一棵指令樹。

```{note}
這一頁是這些平台的說明書，所以它**會**直接寫出文字指令的打法（`!status` 這種）。
Discord 那一側維持原樣：那裡斜線指令是唯一對外介面，文件不教文字指令。
```

目前接好的是 Telegram。之後的平台會接在同一個介面上。

## 一個平台一個行程

**每個開著的平台各跑一個受監督的行程。** 一個行程跑全部的話，一個平台的相依套件
炸掉、一次重啟、一次記憶體用盡，都會把其他平台一起帶走；而「重啟其中一個平台」這
種再普通不過的維運動作會變成「重啟全部」。

每個行程各自有：

- **自己的單一實例鎖**（`state/<平台>/`），所以第二個平台不會被第一個平台擋掉；
- **自己的記錄檔**（同一個目錄），所以一個平台的崩潰原因不會被另一個平台的輸出擠掉；
- **自己的狀態檔**——工作階段、問答佇列、事件、稽核、收藏、排程，全部落在
  `state/<平台>/<平台>.<檔名>`。**平台之間沒有共用的可變狀態**，所以在一個平台開的
  對話不會出現在另一個平台，也不需要任何跨行程的鎖；
- **自己的排程工作**（`install_autostart.py` 會替每個開著的平台各註冊一筆）。

**一個行程只連自己那個平台。** 即使設定裡同時開著三個平台，每個行程也只會連它
`--platform` 指到的那一個——不然同一個憑證上會跑出兩條連線、每則訊息被處理兩次、
互動被兩邊搶著回覆，而兩邊的紀錄看起來都正常。預設平台的連線由**它自己那個行程**
持有，其他平台的行程根本不登入它。

```{note}
這條的代價要講清楚：**沒有登入就沒有那個平台的頻道**，所以由背景迴圈主動貼出去的
東西（批次事件回報、每日健康報告、狀態鏡像）只發生在預設平台那個行程上。單輪的
問答與指令完全不受影響——它們回的是**收到訊息的那個對話**。
```

一次把它們全部拉起來：

```
py -3 start_platforms.py
```

只想看「哪些會起來、哪些不會、為什麼」：

```
py -3 start_platforms.py --list
```

只跑其中一個：

```
py -3 start_discord_bot.py --platform telegram
```

```{note}
**要同時跑兩個平台，要做的就是兩件事**：把那個平台的 token 檔填好，並在
`bot_config.json` 的 `platforms.<名稱>.enabled` 設成 `true`。其餘都是自動的——
狀態目錄、鎖、記錄檔、排程工作都以平台名命名。
```

### 出圖批次仍然只有一份

批次是**全機共用**的（一個瀏覽器、一組佇列檔、一個輸出目錄），所以它不跟著平台分身。
誰先拿到批次監督鎖，誰就負責監督它；其他平台的行程收到批次控制指令（啟動、停止、
單張產圖）時會回一句「另一個行程已經在監督」，而不是另外開一套——兩套監督會互相
終止、互相重生，而且兩邊看起來都正常。

佇列與設定本來就在磁碟上，所以**從哪個平台編輯佇列都一樣有效**；只有「誰監督批次」
這一件事認鎖。

## Telegram

### 一、拿一個 bot token

在 Telegram 裡找 **@BotFather**，`/newbot` 建一個機器人，它會給你一串
`<數字>:<英數字串>` 形式的 token。

### 二、把 token 放進檔案

寫進 repo 根目錄的 `telegram_bot_token.md`，整個檔案就是那串 token（也接受
`token: <值>` 一行的寫法）。

```{warning}
**這個檔案與 `discord_bot_token.md`、`auth.md` 一樣永不進版本庫**——repo 只帶
`telegram_bot_token.example.md` 範本，複製成 `telegram_bot_token.md` 再填。
**檔案是空的就等於「沒設定」**——那個平台安靜地不啟用，bot 其餘部分照常。
```

### 三、填設定

`bot_config.json` 的 `platforms.telegram` 區段：

| 鍵 | 預設 | 說明 |
|---|---|---|
| `enabled` | `false` | 總開關。`false` ＝完全不啟用，連 token 都不會讀 |
| `owner_user_ids` | `[]` | **這個平台上**的擁有者使用者 ID（字串）。空清單 ＝ 這個平台上沒有人過得了主機控制閘 |
| `allowed_chat_ids` | `[]` | 這個平台的「設定對話」ID（字串，群組通常是負數）。等同 Discord 那側的 `channel_id`：非擁有者只能在這些對話裡下指令。空清單 ＝ 只有擁有者用得到 |
| `poll_timeout_sec` | `30` | 長輪詢一次等多久 |

範例：

```json
"platforms": {
  "telegram": {
    "enabled": true,
    "owner_user_ids": ["123456789"],
    "allowed_chat_ids": ["-1001234567890"],
    "poll_timeout_sec": 30
  }
}
```

要查自己的使用者 ID 或某個群組的 ID：找 **@userinfobot** 之類的工具機器人，或
先把 `enabled` 打開、對 bot 說一句話，然後看主控台的記錄。

改完要 `/sys restart` 才生效（整份 `bot_config.json` 都是開機讀一次）。

### 四、怎麼下指令

兩種輸入：

- **`!` 開頭**＝指令。例如 `!status` 看批次狀態、`!queue` 看佇列、`!help` 看
  說明。指令名與 Discord 那側的文字表面完全一樣，一份實作、一組權限閘。
- **其他任何文字**＝直接問問題，等同 Discord 的 `@bot <文字>`。

```{tip}
多行參數直接換行貼上就好，也可以把整段包在三個反引號的程式碼區塊裡——文字表面
本來就是為了「選單做不到的事」留的。
```

### 做得到與做不到

| 能力 | Telegram | 說明 |
|---|---|---|
| 文字指令 | ✅ | 與 Discord 的文字表面同一份實作 |
| 自由提問 | ✅ | 私訊裡直接打字即可；群組裡只有擁有者的一般文字算提問，其他人的一句話不會換來回覆 |
| 編輯已送出的訊息 | ✅ | 所以問答的即時預覽（整回合編輯同一則訊息）在這裡也看得到 |
| 傳檔案／圖片 | ✅ | 單檔上限 50 MB；收進來的附件上限 20 MB |
| 「正在輸入」 | ✅ | |
| 斜線指令選單 | ❌ | 那是 Discord 的原生功能，這裡用文字指令 |
| 表情符號反應觸發的功能 | ❌ | 收藏／刪除那一組只在 Discord 有 |
| 排版 | 純文字 | markdown 刻意不開啟：一段沒跳脫好的符號會讓整則訊息被平台拒絕，答案直接消失 |

其他已知邊界：

- **重開機之後不補跑舊指令。** bot 停機期間累積的訊息一律丟掉。這條路可以在主機
  上執行指令，而「重啟之後突然重跑一批不知道多久以前的主機控制指令」比「漏掉一
  則訊息」危險得多。
- **轉發進來的指令不會執行。** 轉發訊息的寄件者是轉發的人，內容卻是別人寫的；
  照跑的話，轉發一則別人的指令就等於以你的身分在主機上執行它。轉發的一般文字照樣
  可以拿來提問。
- **跨平台的錨點還沒接。** 在這個平台排進佇列、之後才跑的工作（撞到用量上限而
  停放的提問、`/run in` 這類延後啟動），回覆會回到 Discord 的設定頻道，或者因為
  找不到原訊息而停進失敗清單。單輪的問答與指令不受影響。

## 權限：每個平台各有自己的擁有者

Discord 的擁有者 ID 在別的平台上不成立，所以**每個平台各自在設定裡列自己的
`owner_user_ids`**。判定是 fail-closed 的：

- 列在 `owner_user_ids` 裡 → 擁有者，主機控制指令全部可用；
- 其他人、或者根本取不到身分 → **一律不是擁有者**，主機控制指令一律拒絕；
- 不在 `allowed_chat_ids` 裡的對話，非擁有者的訊息**安靜忽略**（不回話——回話等
  於對任何陌生人確認這個帳號後面有東西在跑）。

別的平台的使用者也拿不到 `user_roles` 的角色、也不會被當成「可露完整主機路徑」的
對話，即使把他們的 ID 填進那些清單也一樣。

## 沒設定的平台就是不存在

沒有在設定裡打開的平台**完全安靜**：不啟動行程、不連線、不印警告、也不註冊排程
工作。憑證檔不存在或是空的，也一樣——那是**缺席**，不是失敗。

只有兩種情況會出聲：「開關打開了、憑證卻讀不出來」與「開了卻沒填擁有者 ID」。那
兩種的症狀都是「看起來沒生效」，不講的話沒有人查得出來。

要知道某個平台為什麼沒起來，跑 `py -3 start_platforms.py --list`：它會逐平台印出
原因（關著、或憑證檔不存在／是空的）。

**預設平台也可以關掉**：`platforms.discord.enabled` 設成 `false` 就好。沒有那一格
時它視為開著（否則第一次 clone 下來的 bot 會什麼都不做，而症狀跟設定沒生效一樣）。
